## 1. 모바일 앱 전환 검토 (2026-09-05 지시)

**무엇** — 지금은 브라우저 웹앱이다. 네이티브/하이브리드 앱으로 옮길지 검토한다.

**왜 검토 대상이 되었나 — 이번 사이클에서 측정된 사실**

| 판독 엔진 | 안드로이드 크롬 실측(합성 32케이스) |
|---|---|
| 브라우저 내장 BarcodeDetector | 24/32 |
| zbar(wasm) | 17/32 |
| zxing(wasm) | 16/32 |

- 안드로이드는 **브라우저 내장 엔진**이 wasm 엔진들을 크게 앞선다.
- **iOS 사파리에는 내장 엔진이 없다**(WebKit 미구현). 즉 아이폰 사용자는
  가장 약한 경로인 wasm 으로만 돌게 된다. 이것이 앱 전환을 검토할 실질적 근거다.
- 네이티브로 가면 iOS 는 Vision 프레임워크, 안드로이드는 ML Kit 을 쓸 수 있고
  둘 다 지금의 wasm 경로보다 우수하다.

**검토할 갈래**
1. 그대로 웹 유지 + iOS 는 wasm 사다리로 감수
2. Capacitor/Cortex 류 하이브리드 — 화면은 그대로 쓰고 스캔만 네이티브 플러그인
3. 완전 네이티브 재작성

**검토 전 필요한 것**
- 실제 사용자의 기기 비율(iOS/안드로이드). 지금은 모른다.
- iOS 실기기에서 `/scan-lab` 을 돌린 수치. 아직 없다(에뮬레이터는 안드로이드만 확인).

**언제** — 미정. 실사용 기기 비율이 나온 뒤 결정한다.

## 2. 엑셀 「중고최고가」 열 (2026-09-05 요청, 데이터 없음)

요청받은 주요 열은 `제목/정가/중고가/중고최고가/최저가/중고수량` 인데,
**중고최고가만 현재 데이터 소스에 없다.**

- 알라딘 `ItemLookUp` 의 `subInfo.usedList` 는 채널별로 `itemCount` 와 `minPrice` 만 준다.
  (`aladinUsed` · `userUsed` · `spaceUsed`)
- 즉 최고가에 해당하는 값이 응답에 아예 없다. 지금 있는 값으로 만들어 내면
  **돈에 관한 숫자를 지어내는 것**이 되어 넣지 않았다.

**선택지**
1. 열을 빼고 간다(현재 상태)
2. 「채널별 최저가 중 가장 높은 값」을 근사치로 넣되 이름을 정확히 붙인다
3. 알라딘 중고 상품 목록을 따로 조회해 실제 최고가를 구한다 — 도서마다 API 호출이 하나 늘어난다

→ **사용자 결정 필요.**

## 3. 로그 보존 기간 (2026-09-05 신설)

`app_logs` 는 계속 쌓이기만 하고 지우는 장치가 없다.

- **비용이 쌓이는 곳**: 클라이언트 로그는 세션마다, 플랫폼 로그는 수집할 때마다 늘어난다.
  방치하면 조회가 느려지고 저장 용량을 먹는다.
- 지금은 화면의 「비우기」로 사람이 직접 지우는 것만 있다.
- **해야 할 것**: 보존 기간(예: 14일)을 정하고 자동 정리를 넣는다.
  자동 삭제는 되돌릴 수 없으므로 기간을 사용자와 합의한 뒤 넣는다.
